# FR5 Stage 6 — Curved-Surface Printing

Stage 5 covers a flat build plate. Stage 6 is the harder, genuinely
different problem: printing on a **curved** (non-planar) surface. The target
is a real one — laying an elastomeric sensor conformally onto a mockup of a
human shoulder, from toolpath curves generated by an external pipeline
rather than a flat-layer slicer.

## What You Build

The two toolpath layers and their surfaces loaded above the build plate,
**one layer selectable and live at a time — RX first, then TX**
(`settled.md` S1.32). Each layer is stitched into a print order by
shortest-path search over its own surface, with the nozzle travelling
between disjoint curve pieces by *hovering* a small clearance above the
surface it hugs — never scraping the mockup or wet traces — then the arm
driven through each layer's path via the Stage 5 IK machinery.

### One live layer at a time

The organising constraint of Stage 6: the RX layer prints, its gaps are
filled with silicone **by hand**, then TX prints and is filled the same way
— two robot passes with a manual step between them (`settled.md` S1.32).

RX and TX are the two offset electrode layers of the printed sensor
(`settled.md` S1.30), and RX goes first, per the supervisor's fabrication
sequence: RX → silicone fill → TX → silicone fill. The measured 2.00 mm gap
between `Surface_Bot` and `Surface_RX_Offset` is a silicone base layer
applied to the shoulder mockup before the RX pass, not a modelling error
(`settled.md` S1.34). The `_verify_*` folders in the asset drop are scratch
output, not part of the asset contract.

Everything downstream of the layer selector is scoped to the live layer —
no toolpath, cost matrix, precompute run, cache file or playback ever spans
both layers:

| Step | Scoped per layer |
| --- | --- |
| Curve + surface display | see visibility rule below |
| Geodesic cost matrix (6.2) | two separate matrices — done |
| Print ordering (6.3) | ordered independently on its own surface |
| Travel hover surface (6.3) | `Surface_RX_Offset` for RX, `Surface_TX_Base` for TX |
| Orientation normals (6.4) | from the live layer's own surface |
| IK precompute + cache (6.5) | `curved_rx.precompute.npz` / `curved_tx.precompute.npz` |
| Playback (6.6) | plays only the live layer, start to finish |

**Visibility rule:**

| Live layer | Visible | Hidden |
| --- | --- | --- |
| **RX** (first pass) | `Curved Toolpath RX`, `Surface RX Offset`, `Surface Bot` | `Curved Toolpath TX`, `Surface TX Base` |
| **TX** (second pass) | everything, including the printed RX layer beneath it | nothing |

This is functional, not cosmetic — `Surface_RX_Offset` sits sealed inside
the `Surface_TX_Base` shell, so with TX shown the RX curves are invisible,
not just cluttered. Full rationale: `settled.md` S1.32.

## Roadmap

### 6.1 — Load and Place the Curved Model ✅ done

**Goal:** Get the curves and their surfaces on screen, sitting above the
build plate and centred where the arm can actually reach them.

1. Small ASCII PLY reader (`read_ply_polyline()`) — these files declare
   `element vertex` + `element edge` and no faces, so `trimesh.load(...,
   force='mesh')` yields an empty mesh; a hand-rolled reader is needed —
   **done**.
2. Reconstruct each polyline (`reconstruct_polylines()`): dedupe vertices,
   build an adjacency map, chain-walk from degree-1 endpoints, and handle
   the 6 pieces that are closed loops with no degree-1 node — **done**,
   verified lossless across all 55 files.
3. Load the 3 OBJ surfaces via the existing `load_mesh()` — **done**.
4. Place everything above the print surface as one 4×4 (`load_curved_model()`,
   `T_placement`): rotate 90° about local X (the CAD data's +z wasn't "up"),
   then translate so the workpiece's own XY bounding-box centre lands on the
   **User Frame origin**, with Z lifting the lowest point to the print
   surface — **done**. The XY target is `CURVED_MODEL_XY_OFFSET_MM` (default
   `(0.0, 0.0)`, i.e. exactly on the origin) in
   `examples/curved_surface_printing/study_config.py`.
5. Register curves with `ps.register_curve_network(...)` (one per layer) and
   surfaces with `register_surface_mesh(...)`. Static workpiece geometry, so
   **no Delta transform** (`settled.md` S1.2) — **done**, behind a minimal
   "Load Curved Model" button.

**Pitfall:** do not derive the placement from the build-plate *mesh's* bbox
centre. It looks like the obvious "centre it on the plate" move, and it is
wrong: `BambuLab_BuildPlate.obj` is a stand-in, 258×276 mm with its origin at
a corner, so its centre sits at plate-local `(129, 128)` and silently adds a
~105 mm outward shift. The FR5's flange reach is `a2 + a3 + d5 = 922 mm` and
reachability falls off a cliff right there — 100% solved below 900 mm, ~50% at
920–950 mm. Centre on the User Frame, which is a *measurement*, not on an asset
whose correspondence to the real fixture is unconfirmed. If you point this at a
different job, re-measure reachability rather than assuming a different offset
is safe.

**Verify:** RX curves sit visibly on `Surface_RX_Offset` and TX on
`Surface_TX_Base`, no geometry below the plate, whole assembly ~296 mm across,
and the assembly's XY bbox centre lands on the User Frame origin.

Full record: `settled.md` S1.29 and S1.48, guide
[`CurvedModel_Loading.md`](../wiki/003_Guides/CurvedModel_Loading.md).

### 6.2 — Surface Mesh Graph & Dijkstra Geodesics ✅ done

**Goal:** Shortest paths between two points that stay *on* the surface.

1. Retain the placed curves/surfaces in world coordinates instead of
   discarding them as locals — **done**.
2. Build two undirected graphs, one per print surface (nodes = mesh
   vertices, edges = triangle edges, weight = edge length) — **done**, as
   flat CSR in Python lists (2.1× faster to traverse than numpy at this
   size).
3. Snap each curve endpoint to the nearest vertex of its own surface —
   **done**, max snap 0.68 mm, comfortably inside the ~1.24 mm median mesh
   edge.
4. Hand-rolled `heapq` Dijkstra (no `scipy`) — **done**. Produces two
   separate 70×70 per-layer cost matrices (113 solves, not 140 — shared
   snap vertices collapse many endpoints onto one source), chunked one per
   frame so the window stays responsive.

Both print surfaces turned out to be single connected components — no
unreachable pairs, no component-handling needed.

**Verify:** Both matrices symmetric, zero diagonal, all finite, and every
path length ≥ the straight-line chord between the same snapped vertices.

Full record: `settled.md` S1.31, guide
[`CurvedModel_Geodesics.md`](../wiki/003_Guides/CurvedModel_Geodesics.md).

### 6.3 — Order the 70 Pieces ✅ done

**Goal:** Decide the print sequence so total non-printing travel is small,
scoped to the live layer.

1. Greedy nearest-endpoint seed plus a 2-opt improvement pass over the 6.2
   cost matrices — **done**, `build_print_order()`.
2. RX first, TX second, ordered independently — **done**, with no travel
   move stitching the two passes together (the manual silicone fill sits
   there).
3. Travel moves hover outward off the surface — **done**, using from-scratch
   normals pulled forward from 6.4 (needed here first for the hover offset).
   The hover distance is `CURVED_TRAVEL_HOVER_MM` in
   `examples/curved_surface_printing/study_config.py`, not in
   `geometry_backend.py` — it is a nozzle/material property of *this* job,
   not a property of the arm or the planner (`settled.md` S1.41).

**Verify:** Printed pieces render as a print-order gradient, travel moves in a
distinct flat colour; optimised travel beats naive file order by ~7× (RX 690
vs 5157 mm, TX 607 vs 4848 mm).

Full record: `settled.md` S1.35, guide
[`CurvedModel_PrintOrder.md`](../wiki/003_Guides/CurvedModel_PrintOrder.md).

### 6.4 — Per-Waypoint Orientation from Surface Normals ✅ done

**Goal:** Hold the nozzle normal to a surface that is no longer flat.

1. Replace Stage 5's single constant `R_target` with a per-waypoint rotation
   — **done**, `build_orientation_frames()`.
2. **Z = the outward surface normal** — **done**.
3. In-plane X/Y pinned to a **fixed world reference** rather than the path
   tangent — **done**; the nozzle is rotationally symmetric, so that DOF is
   free, and pinning it gives every waypoint a concrete frame to draw and to
   feed IK.
4. Compute + visualise only — **done**; feeding the array through IK is 6.5.

What this produces is the **nominal** frame: the tool axis the surface asks
for, plus a display triad. Treat it as the *axis of a cone* rather than a
commanded pose — Stage 7.4 searches a 20° tilt cone about this axis and sweeps
the free roll, and this is the frame that cone is built around.

**Pitfall:** the free roll in item 3 is pinned here by picking whichever world
axis is most perpendicular to Z (`argmin |a·z|`). That is a per-waypoint,
*discrete* choice, and it flips as the normal sweeps across the surface —
producing joint steps of up to 180° between neighbouring waypoints in an
otherwise smooth path. Guarding against the projection collapsing is not the
same as keeping the choice continuous. Don't try to patch the rule; a free DOF
chosen independently per waypoint is the defect, and 7.4 resolves it by
searching the roll globally with a continuity cost instead. Path continuity is
deliberately **not** established at this stage.

**Verify:** Every stored `R` is orthonormal with `R[:,2]` equal to the surface
normal to 0.0 across all 2527 RX / 2000 TX waypoints.

Full record: `settled.md` **S1.36**, guide
[`CurvedModel_Orientation.md`](../wiki/003_Guides/CurvedModel_Orientation.md).

### 6.5 — IK Precompute & Playback Reuse ✅ done

**Goal:** Reuse Stage 5's precompute/playback machinery per layer rather
than rewrite it.

1. `run_curved_toolpath_ik_precompute(layer, ...)` feeds Stage 5's chunked
   solver through a new shared seam, `_begin_toolpath_precompute` — **done**.
2. Waypoints come from 6.3's ordered pieces + travel hops, carrying 6.4's
   per-waypoint nominal orientation — **done**.
3. Per-layer disk caches (`curved_rx/tx.precompute.npz`) — **done**; keep the
   planar and curved caches independent, and key each one the Stage 5 way
   (`settled.md` S1.21).
4. The cache stores the **waypoints and the orientation frames** alongside the
   solved joint path — **done**. Saving only the joint path is the tempting
   shortcut and it silently breaks anything downstream that needs to know
   *where* the tool was going, not just where the joints were: after a cache
   hit those arrays come back empty, and Stage 7's exporter would emit an empty
   job. Restore everything a consumer needs.
5. No collision check runs in the curved precompute at this stage — **done**,
   deliberately. See 6.8 for what that leaves open and why the obvious
   candidates don't work.

**Verify:** The planar G-code precompute is an unchanged regression (all
181,375 waypoints); the RX layer solves its full 3,175-waypoint path using
per-waypoint orientation, with FK reproducing each solved pose to sub-micron
accuracy; a cached run and a fresh solve produce identical waypoints,
orientations and joints.

Full record: `settled.md` **S1.37**, guide
[`CurvedModel_IKPrecompute.md`](../wiki/003_Guides/CurvedModel_IKPrecompute.md).

### 6.6 — GUI Wiring ✅ done

**Goal:** Load, clear, precompute and play the curved model from the panel —
reusing Stage 5's controls, not duplicating them.

1. **One source-aware control set** — **done**. A "Toolpath Source" selector
   (`Planar (G-code)` + one entry per layer) sets `toolpath_source`, and the
   *existing* Run/Pause/Cancel Precompute and Run/Pause/Reset Toolpath buttons
   dispatch to the planar or the selected curved layer via it
   (`run_active_toolpath_ik_precompute`, source-aware `*_toolpath_playback`).
   A layer-mixup guard force-cancels a paused run of a different source rather
   than silently resuming it.
2. **Load/Clear Curved Model pair** — **done**, `clear_curved_model()` removes
   every registered curved structure and resets state; gated off
   `curved_model_loaded`, same idiom as the G-code preview Clear.
3. **Curved bead playback** — **done**. `_build_curved_beads(layer)` sweeps a
   fixed-cross-section bead along each waypoint's surface normal (no extrusion
   `E`, no "layer Z" on a conformal path). Its dimensions are
   `CURVED_BEAD_WIDTH_MM` / `CURVED_BEAD_HEIGHT_MM` in `study_config.py`
   alongside the 6.3 hover distance (`settled.md` S1.41). Per-layer bead state
   means a finished layer's printed mesh stays visible under the next.
4. **Stack-rule live view** — **done**. `apply_live_layer_visibility` shows
   layer *k* plus every layer beneath it (`i <= layer`, the S1.32 physical
   stack: TX shows the printed RX layer under it), replacing the provisional
   strict isolation.
5. **Top-down build panel** — **done**. Load Curved Model → a collapsible
   **Curved Model Properties** dropdown (`curved_model_summary()`) → Toolpath
   Source → Build Geodesics + progress + status → Build Print Order + status →
   Build Orientation Frames + status, each stage below the previous one's bar.
6. Controls grey out during playback / mid-solve — **done**.

**Verify:** Headless — pausing RX and starting TX force-cancels RX (no silent
resume); `Curved Print RX` and `Curved Print TX` coexist; `clear_curved_model()`
removes every curved structure and reload re-registers cleanly. Interactive
window — the stack-rule view and the bead reveal look right, with TX printing
over a still-visible RX.

### 6.8 — Collision: What Stage 6 Checks, and What It Defers ✅ done

**Goal:** Be explicit about the gap. The planar path inherits Stage 5's
ground-clearance filter; the curved path has **no collision check at all** at
the end of Stage 6, and that is a known, deliberate hole rather than an
oversight.

Stage 6 drives the arm along a curved path near a physical mockup with nothing
watching for the arm passing through it. That is safe to defer only because
nothing here commands a real robot. Stage 7.4 closes it with a nine-filter
candidate set, including this project's first mesh-vs-mesh collision tests.

Three approaches look obvious at this stage. All three fail, and knowing why is
what makes 7.4's design read as inevitable rather than arbitrary:

1. **An infinite plane through the build plate's top face.** Sound only while
   the plate sits below the whole arm. Measure a real cell and it won't: at a
   User Frame 323.5 mm above the base, that plane cuts through the shoulder and
   elbow — links nowhere near the print — and rejects every valid IK branch at
   the very first waypoint. "Just move the plate lower" stops being available
   the moment the plate height is a measurement rather than a tuning knob. A
   real bed is finite and the arm reaches *around* it, so the model has to be
   finite too: a footprint plus a bounding slab.
2. **A tangent-plane check on the nozzle tip.** Each waypoint's tangent plane
   is a supporting hyperplane for the convex mockup stack, so testing the tip
   against it looks like a cheap proof that everything behind it clears. It
   isn't a check at all: IK pins the tip to that same plane by construction, so
   the test can never reject anything. Measured over 7,471 evaluations it
   rejected zero, with a worst-case violation of 3.4e-13 mm against a 1.0 mm
   tolerance. A check that cannot reject is not a check — measure the rejection
   rate before trusting one.
3. **A full-arm mesh check against the print surface.** Reject this at Stage 6
   and you would be right, for the wrong reason: with **one** commanded
   orientation per waypoint (6.4), a genuine full-arm check rejects nearly every
   real printing pose, because there is no alternative pose to fall back to.
   That reasoning expires as soon as the orientation is searched rather than
   commanded. With ~480 candidates per waypoint, a strict mesh check becomes
   affordable *and* useful — it catches poses that put an arm link fractions of
   a millimetre into the print surface.

`CURVED_TIP_CLEARANCE_TOLERANCE_MM` lives in `study_config.py` with the other
nozzle/material values (`settled.md` S1.41); Stage 7.4's surface-collision
filter is its first real consumer.

**Verify:** Confirm the hole is where you think it is — run a curved precompute
and check that no pose is rejected on collision grounds, then satisfy yourself
that the planar path still rejects a below-plate branch via Stage 5's filter
(5.5). Knowing exactly which path is unguarded is the deliverable here.

Full record: `settled.md` **S1.40**, spec:
[`2026-07-22_stage6.8_posed_plate_collision.md`](../wiki/001_Inbox/2026-07-22_stage6.8_posed_plate_collision.md).

## What's Next: Beyond Stage 6

mesh, a stand-in tool, and one commanded orientation per waypoint. Stage 7
replaces each with a measured value, adds the orientation search and collision
filters this stage deferred, and exports a solved job in the format an external
